# Changelog

Versions follow Semantic Versioning. Desktop behavior is verified manually on Windows (`npm run smoke`); unit tests use mocks.

## 0.7.1

- `acb_gpt_history` reopens the desktop window when the app is still running in the tray. It waits up to ten seconds for a window, gives the foreground back while waiting, then raises and reads the page as before. Opening failures no longer wait for the page-read timeout.
- ChatGPT history and latest-reply page reads retry a `WINDOW` failure once after a short pause, within the original deadline. The retry navigates to the same conversation and keeps the existing title, prompt and turn checks; it never sends a message.
- `acb_gpt_read` with `page: true` still needs the window visible and the page at its end; only `acb_gpt_history` opens a closed window, raises it and scrolls it.

## 0.7.0

- New `acb_gpt_history { conversationId, turns?, skip? }`: earlier turns of a ChatGPT conversation with their whole reply text, read from its page, back to its start; `more` tells whether older turns exist. The app returns only the newest five ChatGPT turns, mostly with placeholders for the replies. The page holds only the messages near what it shows and loads older ones at its top, so ACB scrolls it up step by step (UI Automation ScrollPattern, no input) and joins the steps by the runtime IDs of the messages' headings, so equal turns are not confused; it waits for the page to load older messages before taking its top for the start. For when the user is away, it starts the app if it does not run (through the shell, by the app's user model ID; the foreground it takes is given back), and brings a window that does not show on screen above the others without activating it, putting it back afterwards. About 20 seconds for 50 turns. The page puts a message it renders anew on the page a moment before its reply's text, so a step is read only once every reply in it shows its text; a reply that never does (an image) is returned as `null`, never as empty text.
- `acb_gpt_create` works when the sidebar shows more than one new-chat button, as it now does next to its list of recent chats; the first is used, and the new chat page is still checked before the prompt is written.
- Faster page reads: the Windows helper finds the app's windows with `EnumWindows` instead of walking the desktop's UI Automation tree (about 150 ms each time), and reads the page's tree in compiled code instead of PowerShell (about 200 ms for a long conversation). A read of the page takes 50-110 ms instead of 200-320 ms, which every reply read from the page and every step of `acb_gpt_history` benefit from. The app's conversation and its list are fetched together where both are needed, and the first call checks the tool pipe's owner from its process token instead of WMI (about 0.8 s less).
- The Windows helper sets per-monitor DPI awareness itself instead of relying on UI Automation to make it DPI-aware, so screen and window bounds are in physical pixels on every monitor.

## 0.6.1

- **Faster ChatGPT replies**: the app records a ChatGPT turn up to a minute after it ends (it caches conversations for a minute, and none of its tools refreshes them). `acb_gpt_send` now shows the conversation before sending and returns as soon as the page's user messages end with those it showed before plus the new one and the reply is finished: about 10-20 seconds instead of 60-90. (The page holds only the messages near what it shows, five or more, so it is compared on those, and on two at least, and only while it is scrolled to the end.) Such a turn has `turnId: null`; until the app records it, `acb_gpt_read` in the same process returns it, and sending the same prompt again returns it without waiting. Without a usable page, the app's list is still awaited.
- Page text follows the page's structure: a reply being written is one UI Automation element per word, which used to come out one word per line. The page is now fetched as one cached batch of its raw tree, and its text is joined within paragraphs, list items and code lines, with line breaks between them and list markers kept (a read takes 150-400 ms).
- Messages ACB sent that the app does not list yet are kept in order, and matched to the app's turns in that order once it lists them, so a prompt sent twice (A, B, A) gets its own turn, and a message that certainly failed no longer drops the record of the one before. When the app no longer returns the turn the messages followed (it returns five ChatGPT turns), they are no longer matched by position, and a message whose delivery is unknown is never sent again on its own (`TIMEOUT`). The page is checked inside the conversation's lock: a busy page refuses the send (`BUSY`); a page showing the prompt as its newest message, after the messages known, is not sent to again; a page showing messages after those known overrides the app's list and ACB's records on which message is the newest; and a page that cannot be matched to the known messages refuses any send that depends on which message is the newest.
- Fixes: a reply in a conversation with more than five turns could not be read from the page (the app returns only the newest turns, so the count of page messages never matched); a prompt with `inline code` never matched the page, which shows it without backticks. The page must now end with the prompts of the turns the app lists, on two reads in a row, compared exactly except for the backticks of inline code; recent prompts that repeat in a cycle are refused, since an older state of the page would match them too. The page is read only while its window shows on screen (not minimized, fully covered or on another virtual desktop, judged as Chromium does), since the app does not update it otherwise. When the page is a turn ahead of the app, `WINDOW` says to read again shortly.

## 0.6.0

Rebuilt on the tools the desktop app serves to its own agents. Every message now runs inside the app, so conversations and their progress appear live in its sidebar.

- **Codex** conversations are created, messaged and read through the app (`create_thread`, `send_message_to_thread`, `read_thread`) instead of a separate `codex app-server`. ACB no longer looks for `codex.exe`. A Codex turn waiting for approval returns `NEEDS_USER` at once instead of being declined; approvals are left to the user in the app. `wait: false` returns right after sending.
- **ChatGPT** messages are sent in the background through the app; the window is no longer activated and nothing is typed. The reply text is read from the page without activating the window. A page that cannot be read (window fully covered) no longer fails the send: the result keeps `replyOnPage` and says why. `acb_gpt_create` takes the first `prompt` (and an optional `title`) and returns the first reply; it is the only tool that brings the window to the front, and it writes the prompt through UI Automation instead of keystrokes.
- Tools: `acb_gpt_open` became `acb_open` (any conversation); `acb_codex_create` takes `prompt`, `title`, `projectId` or `folder`; reads return `status` (`idle`, `running`, `needsUser`) and turns with `prompt`, `reply`, `replyOnPage`, `truncated`. Removed: `acb_threads` (use the list tools), `acb_codex_find` and `acb_workspace_create` (the app has no search, and creates folders itself), and the `--allow-foreground-input`, `--codex`, `--config` and `--debug` options (the first is still accepted and ignored).
- Safety: a request is repeated only when it provably never reached the app; sends to one conversation are serialized, and a message ACB sent (or may have sent) is not sent again until the app lists a turn it opened; prompts are limited to 20,000 characters so ACB can always read them back whole; a reply read from the page must belong to the newest turn: the page must show as many messages as the conversation has turns, the last with the exact prompt, under a title no other listed conversation has; if the app takes the foreground while switching pages or opening a new chat, ACB hands it back; the server of the app's pipe is checked (OpenAI-signed app of the current user and session).
- Errors are `UNAVAILABLE`, `NOT_FOUND`, `BUSY`, `NEEDS_USER`, `TIMEOUT`, `FAILED`, `WINDOW`, `INPUT` and `PROTOCOL`.
- Configuration is `--caller` / `ACB_CALLER` and `--timeout` / `ACB_TIMEOUT` (seconds). The caller defaults to the most recent Codex conversation the app accepts.
- Smaller and faster: about 1,400 formatted lines instead of 1,900 densely packed ones (the UI Automation script shrank from 640 to 150 lines); the app is reached directly over its named pipe (reads take 20-30 ms), and the PowerShell helper is used only for the pipe check and the ChatGPT page. Formatting and lint by Biome.

## 0.5.0

- Independent tools instead of one workflow: new read-only `acb_codex_list` (thread/list, by `cwd`, with a cursor) and `acb_codex_read` (newest 1-20 turns through the App Server), `acb_gpt_list` and `acb_gpt_read` (newest 1-10 turns by ID through native IPC, `nextCursor` for older turns, no window). The server instructions, README and skill describe each tool and the safety rules; the Hermes → GPT → Codex roles and workflow diagram are removed. Existing tool names and arguments are unchanged.
- Desktop app v26.1021: app tools (`tools/call`) moved from `codex-browser-use-<uuid>` (now ping and browser automation only, "No handler registered for method: tools/call") to `codex-app-tools-<uuid>`. The pipe worker prefers the new pipe and falls back to the old one; host verification is unchanged. `read_thread` accepts `turnLimit` 1-10 and an opaque `cursor`.
- A rejected native request keeps the host's error code and message (`nativeError`), a failed tool keeps its text, and a refused request restarts the pipe worker so a restarted app is found again. A host that cannot list its ChatGPT chats is a `DEPENDENCY` error, not an empty inventory.
- The auto-discovered `codex.exe` is discovered again before every use, so a server started before a desktop app update no longer fails with `DEPENDENCY` (2026-10-21 incident); a configured path that no longer exists fails fast with a fix.
- `acb_gpt_read`: the host empties message text when outputs are excluded, so reads keep outputs on; a reply kept in the transcript only as `::chatgpt-content-reference{…}` is reported as `reply: null, replyInWindowOnly: true`, and `window: true` reads the newest reply from the shown chat through the same UIA path as `acb_gpt_send`.
- A minimized ChatGPT window exposes no UI tree in the current app, so it could never be identified and the documented restore never happened (`OWNER` at `chatgpt-window`). With `--allow-foreground-input`, the app's only window is now restored once when minimized and unreadable, then identified as before; a Codex or unidentified window is still refused. Window-choice failures report window counts in `diagnostics` and a fix.
- Removed `acb_gpt_create`'s `project` argument (start a chat inside a ChatGPT project). Creating a ChatGPT conversation does not need it, and v26.1021 no longer shows the project picker (更改项目) it relied on. Clients passing `project` now get an invalid-arguments error.
- Archived Codex conversations were never unarchived: the App Server already refuses `thread/resume`, before `turn/start`. Resume and start are now retried together once after unarchiving.
- Faster: read-only tools no longer wait behind a running send; the App Server, desktop context and pipe/UI workers start in the background when a client connects (first call 5.1 s -> 0.4 s); Codex sends and reads load thread metadata and the newest turns instead of the whole history, which also keeps long conversations under the frame limit.
- `acb_status` reports the server's pid and start time, the native host's app version and pipe type, and the pipe counts. `npm run smoke -- --scope codex|gpt` checks one group.
- The repository and its folder are named `agent-control-bridge`.

## 0.4.0

- Housekeeping: the unused native tool catalog (`tools/list`) is removed from the client and the pipe worker's request allowlist; both configuration examples live in `config/`.
- Installable MCP tool: `npm install` builds it, `npm run check` (or `--check`) runs a read-only self-check and prints the Hermes `mcp add` and skill commands for the machine. No configuration is required: `codex.exe` is discovered from the Codex desktop app (or PATH) and the desktop context thread from the most recent Codex conversation; options, `ACB_*` variables and an optional JSON file still override.
- Hermes skill `skills/agent-control-bridge` with the working rules (roles, reuse, short reports, failure handling, approval for non-core work).
- One Codex App Server process is reused across calls (closed after 10 idle minutes or on failure) and a `turn/completed` notification ends a reply wait without waiting for the next poll.
- New `acb_status` tool. UIA stage lines are logged only with `--debug` / `ACB_DEBUG=1`. Child processes are closed when the client disconnects.
- Default send timeout 240 s, below Hermes' 300 s tool timeout, so a long reply returns a clean `TIMEOUT` (read it later with the same prompt; it is not resent).
- `scripts/acceptance.mjs` is now `npm run smoke`; carrier thread and Codex path are optional there too. Obsolete review templates and duplicate rule documents are removed; README rewritten with architecture and workflow diagrams.

## 0.3.0

- Reduced to the core bridge: workspaces and Codex projects, GPT/Codex conversations, locating a target, sending one prompt and returning the real reply. Codex goes through the App Server (`project/create`, `thread/start`, `turn/start`, `thread/search`, archived threads unarchived once, approvals declined). ChatGPT is located through the native inventory and its single sidebar entry, typed into with authorized SendInput (never taking the foreground), and new chats are identified by a one-time marker.
- Windows fixes from real runs: offscreen sidebar entries, the new-chat composer, transient Codex readback errors, ChatGPT/Codex window choice, PowerShell workers with UTF-8 BOM, and new chats inside an existing ChatGPT project with read-back confirmation.
- Removed: SQLite ledger, caller policy and roles, approvals, tasks and background worker, notifications, CDP/Python tools. The previous architecture remains in the Git history.
