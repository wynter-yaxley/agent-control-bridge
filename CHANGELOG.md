# Changelog

Versions follow Semantic Versioning. Development delivery remains pending independent acceptance; formal Release requires an accepted tag and evidence.

## 0.3.0 (Unreleased)

- Codex workspaces, projects and conversations now use the App Server contracts measured on Windows: acb_workspace_create (directory + project/create with a per-directory idempotency key), acb_codex_create (thread/start {cwd}, first turn to persist, thread/name/set), acb_codex_find (thread/search). acb_codex_send unarchives a thread once when turn/start refuses it and reports declined approvals. The workspace UIA dialog flow and the native create_thread/navigate/move writes are removed.
- ChatGPT: navigate_to_codex_page is gone (it does not open ChatGPT chats); a chat is located when already shown or through its single sidebar entry when its title is unique. Input is either the user's identical draft (sent as is) or SendInput typing with ChatGPT already in front; the bridge never takes the foreground and returns FOCUS_REQUIRED instead. The UIA document is re-acquired up to three times when the tree is briefly unreadable. maxCandidates defaults to 32. ChatGPT-native projects are not implemented.
- Core creation and navigation on top of forwarding: acb_workspace_create (directory + native project via the app's project dialog, reusing a registered directory), acb_gpt_create (new ordinary chat identified by a one-time marker turn, named with native set_thread_title, optional move into a project), acb_codex_create (native create_thread in a local project), acb_gpt_open (navigation by ID with native navigate_to_codex_page; a sidebar click only for a title unique in the native inventory), acb_projects.
- ChatGPT input uses foreground SendInput (UIA SetValue has no effect on the composer), only with --allow-foreground-input; foreground window and focus are checked before every chunk, the text must read back within ~10 s, and on failure only the worker's own text is cleared.
- Reduce the bridge to its core: forward a prompt from Hermes to an existing ChatGPT conversation (UIA send + Native IPC completion + UIA reply) or an existing Codex thread (codex app-server) and return the reply. Three MCP tools: acb_threads, acb_gpt_send, acb_codex_send.
- Removed: SQLite ledger and migrations, caller policy and roles (controller/executor/reviewer), approvals, tasks and background worker, notifications/Feishu, workspace/GPT/Codex creation and recovery, CDP/Python desktop tools, release/history scans and their tests. The previous version stays on branch codex/github-sync-20261012.
- Kept protections: target title read natively and checked before the composer is touched, UUID check when the page exposes one, no resend of a prompt that is already the latest turn, busy/draft refusal, one send at a time, Codex approvals declined, signed same-user Native IPC peer.

## 0.2.0

- READY projects can add Codex conversations without changing the original request fingerprint: acb_project_attach_codex now also attaches to READY projects, and new acb_project_create_codex formally creates one per call with its own reviewer approval. Both require sole controller access, a mapping that matches the verified resources, an unclaimed ID (no other project, operation or GPT) and native readback of kind, projectId, cwd and workspace name; at most 4 per project. A formal creation records its pending index before the native call; a lost receipt keeps the project READY with stages.codexPending and the next call only reads the original receipt. Repeated attaches are idempotent; every addition is audited.
- Formal native Codex creation through create_thread: installed by the composition entry with desktop.enabled on a controller connection. It reads the catalog first and calls only if the schema accepts exactly title, prompt and a project target; the pipe worker allows create_thread only with an acb-create- call ID, a UUID projectId and the fixed Codex identity prompt. The prompt ACB_CODEX_INIT_<operationId>_<index> is the durable receipt: a lost reply or crash is recovered from the unique Codex member of the workspace/directory carrying it (also for codex.extra), never by title, never resent. A creation refused before any effect (reviewer rejection or timeout, incompatible schema, rejected parameters) moves the bundle to codex.attach instead of leaving it uncertain, and on a READY project releases the pending index. Unverified on a live desktop.
- GUI initialization approvals are bound to one operation attempt: the ledger approval names operationId, attempt and effects (native-workspace, ordinary-gpt, codex-thread) and is reused only within that attempt, for listed effects, while the operation row still names this controller, name and path and is PROVISIONING/READY. Restart, reconcile and each added Codex are new attempts and ask again; a failed attempt is not reused.
- The native add-project entry is probed read-only before any approval, directory or restart budget: it must be the single enabled, on-screen, invokable button; an offscreen one gets one ScrollItemPattern scroll and is re-read. Otherwise the request stops with STATE and reports the entry state (offscreen, enabled, patterns, ancestor types/automation IDs; no UI text). The worker never invokes hidden, disabled or non-invokable controls, and creation failures report whether any native effect had started. Preflight adds the entry state and create_thread compatibility.
- Fix native identity checks for older threads: list_threads returns only the 30 most recent threads, so Codex membership checks (executor target inspection, bundle verification, adoption, receipt recovery) failed once a project's thread aged out. Recorded IDs outside that window are now read exactly with read_thread and accepted only when that read names the same thread with matching kind, projectId and cwd.
- Without a formal native Codex creator, a bundle no longer stops before creation or ends UNCERTAIN: after the workspace and GPT it waits in BLOCKED/CODEX_ATTACH_REQUIRED (phase codex.attach), and acb_project_attach_codex accepts operator-created conversations only after native readback shows them as Codex members of that workspace and directory. Attachments are audited and idempotent; the bundle verifies and registers when the requested count is reached.
- The composition entry can create bundles when desktop.enabled is set on a controller connection: GUI initialization is a ledger approval (gui-initialization) decided by an independent reviewer, reused only for the same name/path for 10 minutes; its helper task is cancelled afterwards. Without the flag the native project host stays read-only.
- GPT creation reports each UIA step and awaited control (gpt-new-chat … gpt-rename-confirm), waits within budget for the page Document and the rename save button, and preflight lists native catalog tool names.
- Fix Windows drive-root workspace roots: an existing root (for example D:\) is no longer passed to mkdirSync({recursive:true}), which fails with EPERM; only the new workspace directory is created. Symlink, containment and existing-directory checks are unchanged.
- Native workspace creation reports which step and control timed out (workspace-add-button … folder-consent-close). The worker's budget is 5 s shorter than the outer deadline so it reports first; stage lines include the awaited control, and creation failures emit a bounded, text-free structure survey (ACB_UI_DIAGNOSTIC) on stderr. Project failure notifications carry this detail. Control names are unchanged pending current-version UIA evidence.
- Project operations expose stages (directory, native workspace, GPT, Codex count). A lost workspace step still only reconciles by readback; acb_project_restart_workspace adds an explicit, host-approved, audited retry (max 2) only when the holder exited, the operation's own directory is empty and no native workspace exists for it. Native creation refuses a directory that is already registered and an ambiguous readback.
- acb_project_prepare accepts codexConversations (1–4). Each additional Codex conversation needs its own formal receipt naming a new thread of the same workspace (cwd/projectId checked on verify); repeats are refused and a lost extra receipt stays UNCERTAIN. Bundles are refused before any directory or UI effect when the host reports no formal Codex creation.
- Windows composition without an embedding: a protected-policy executor entry with "host": <controller SID> is the controller's only delegated Codex executor (distinct principal/instance, never a reviewer). Codex command/file approvals become ledger approvals decided only by an independent reviewer (new acb_approvals_pending / acb_approval_decide); stale turns, out-of-workspace cwd/grantRoot, secrets, cancellation and timeout decline. --worker names each missing prerequisite.
- Add read-only `windows-host --preflight` (policy roles, delegation, schema, unowned legacy projects, Codex config, CDP listener, bounded UIA survey, native counts). The UIA worker gains a bounded `uia-diagnose` survey (types/classes/depth/patterns only) and briefly retries the Document lookup for lazily built accessibility trees; real-desktop effect is unverified.
- Legacy re-binding: acb_project_adopt grants access and the native workspace ID only after native readback of the recorded GPT/Codex IDs (Codex membership selects the project; name alone never does). Writing a mapping no longer claims an unowned migrated project.
- Restrict historical scan acknowledgements to the two exact paths/blobs in the initial import. Scan later reuse and every file path, reject baseline expansion, and report pending Hermes policy review; preserve published Git history.
- Verify pinned Codex threads during native bundle recovery and Executor target inspection with the same project/directory checks as other threads. Windows regression uses the fixed system PowerShell ACL helper and closes every SQLite handle before temporary-directory cleanup.
- Make the release check deterministic: local user paths are matched for any concrete /home or \\Users account (placeholders excepted) instead of only the account running the check. Two registered blobs of the published initial import are listed by hash in scripts/check-history-baseline.json and reported as acknowledgedHistory pending independent policy review; current-tree or new findings still fail.
- Record the project holder atomically with PROVISIONING. Reconciling an operation that crashed before any resource receipt (no phase, no resources, no directory) returns it to BLOCKED so the same request can retry; an unexplained directory stays UNCERTAIN.
- Windows ordinary GPT creation requires the recorded operation key; a random marker could never be verified after restart. The CDP reader maps the worker's zero-selector exit to PROVENANCE instead of an unstructured IO failure.
- Add an isolated v2 ledger test with committed but un-checkpointed WAL pages: online backup keeps them (a raw main-file copy does not), the backup migrates to v6 with integrity/foreign keys/rows intact, grants no project access, and restores only into new files.
- Fix cross-process project recovery: bundle verification no longer depends on an in-process GPT ID cache that a restarted Bridge lacks, nor on a UIA conversation ID the current ChatGPT build does not expose. A fresh host re-reads native project/thread membership and the operation's exact ACB_INIT receipt; no GUI, recreation or resend. Foreign same-title chats and Codex threads of other projects stay rejected.
- UIA title fallback reports the failed worker stage (interactive desktop, ChatGPT process, unique window, document) and treats an empty Document name as unavailable instead of titleOnly. A missing ChatGPT process no longer surfaces as a generic EXECUTION error.
- Synchronize original RUNNING_OBSERVED completion across task/run/request, check affected rows, and make completed reconciliation avoid duplicate feedback/notifications. Reject unrelated normal RUNNING recovery.
